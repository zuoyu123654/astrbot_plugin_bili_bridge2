# astrbot_plugin_bili_bridge · B站动态记忆桥

让 QQ 里的 AI 真正「看过」你在 B站 刷了什么，并且你追问某条视频讲了什么时，它会**现去拉字幕**再讲，而不是照抄摘要。

> 一句话：**B站 那边每天挑了什么 → 变成它的记忆；你问细节 → 它去 bili-cli 读字幕。**

---

## 它做三件事

### 1. 记忆同步（后台，定时）

定时（默认 10 分钟）读取 B站 侧的挑选结果，压缩成一小段清单，写进 **MemoryCompanion 的核心记忆块**。核心块每轮对话都会无条件注入，所以「B站 今天看了什么」这类问题答得出来。

每一轮的块固定 **5 条**：

- 最新的 **2 条挑中并已私信**的视频（`block_picked` 可调）；
- 从这一轮**跳过**的视频里随机抽 **3 条**（`block_skipped` 可调）——这样问「最近看了什么」时，它能说出挑了什么、也放弃了什么，而不是只报几个标题。

判断“这一轮”用 **BV 号**：没见过的才算新的。digest 文件会被写入端重排、改写，按行数差判断会漏掉最新的几条，所以不用行数。

每跑一轮，这一块整体替换成那一轮的内容；没有新 BV 时不重写，避免无谓的上下文变动。

**长期记忆**：除了这块会被覆盖的核心记忆，每一轮「挑中」的视频还会单独写一条带日期的长期记忆（按这一轮的 BV 集合去重，不会重复写）。所以过几天问「前两天推过什么」也查得到。

**历史搜索**：装了 `bili_search` 工具，可以按标题关键词、BV 号或日期去翻所有历史 digest 文件，不占记忆额度。

> 写入时机取决于 `sync_interval`（默认 600 秒）。想更贴近实时可以调到 120～300。

挑选结果的默认位置是 `~/.dsh/bili-duty/digest/YYYY-MM.md`（由刷视频类工具生成），每行格式：

```
2026-11-02 · BV1vynb6tEW5 · 标题 · UP主 · 值得看：一句理由 · https://www.bilibili.com/video/xxx
```

带「跳过」字样的行不会进记忆（可配置关键词）。

### 2. 按需解析（工具）

注册 LLM 工具 `bilibili_read(bvid)`：

- `bili video info` 取标题、UP、时长、播放/点赞/收藏/评论、简介；
- `bili video subtitle` 取字幕原文（截断到可配置上限）；
- 没字幕就退 `bili video summary`（B站 官方 AI 总结）；
- 同一个视频按 TTL 缓存（默认 1 小时），问两遍不重复跑。

### 3. 处理 QQ 分享卡片

QQ 的「分享视频」是 **JSON 卡片消息**：`message_str` 是空的，链接藏在卡片结构里，而且常常只有 `b23.tv` 短链。

插件会：把卡片内容整体取出来 → 正则找 BV 号 → 没有就跟随短链跳转解析出 BV → 给没有文字的消息补一段可读文字（不补的话 AstrBot 会判定消息无效，模型根本不会被叫起来）→ 在请求前把视频素材注入。

## 依赖

- **AstrBot** ≥ 4.17
- **MemoryCompanion 插件**（`astrbot_plugin_memory_companion`）—— 记忆写入靠它；没装的话同步功能会自动跳过并提示
- **bili-cli**（pip 包 `bili-agent`，装好后命令是 `bili`），并且**已登录** B站 账号
- 刷视频类工具（可选）：如果你没有 `~/.dsh/bili-duty/digest`，可以把 `digest_dir` 指到任何符合上面行格式的目录

插件本身不引入任何第三方网络库；只有解析 `b23.tv` 短链时会用到 AstrBot 自带的 `aiohttp`（没有也能跑，只是短链不解析）。

## 安装与配置

1. 把本仓库放进 `AstrBot/data/plugins/`（或用插件市场安装）。
2. 重启 AstrBot，打开 WebUI → 插件 → **B站动态记忆桥**，填这几项：

| 配置项 | 说明 | 建议 |
| --- | --- | --- |
| `bili_executable` | bili-cli 可执行文件 | PATH 里有就写 `bili`，否则写绝对路径 |
| `digest_dir` | 挑选结果目录 | 留空 = `~/.dsh/bili-duty/digest` |
| `owner_uids` | 允许触发的 QQ 号（逗号分隔） | **必填**，否则任何人都能触发解析 |
| `memory_user_ids` | 记忆写到谁的记忆里 | 留空 = 沿用 `owner_uids` |
| `core_max_chars` | 核心块字数上限 | 默认 700；MemoryCompanion 全部核心块预算通常只有 800 字 |
| `detail_hint` | 写进记忆的用法提示 | 默认已包含「要分点讲、可以两三百字」 |

### 可选：把 B站 私信转到 QQ

如果你在 B站 那边会收到推荐私信（刷视频类工具常把挑选结果私信给你），可以让插件把新私信转发到 QQ：

| 配置项 | 说明 |
| --- | --- |
| `dm_forward_enabled` | 打开转发 |
| `dm_owner_uid` | 监听哪个 B站 用户的私信会话（一般填你自己的 UID） |
| `dm_target_session` | 转发到哪个 QQ 会话，形如 `qq-main:FriendMessage:1792559819`（平台 id 以 WebUI 里实际显示的为准） |
| `dm_poll_interval` | 轮询间隔，默认 180 秒 |
| `dm_mark_read` | 拉到之后是否在 B站 侧标已读，默认关 |

行为说明：**第一次运行只记录水位、不补发历史**；之后只推水位之后的新私信。发送失败不会推进水位，下一轮会重试——所以启动早期平台还没连上也不会丢消息。


### 关于「讲详细一点」

人设里常写「短句、1~3 句」，模型会严格执行，于是拿到 1800 字字幕也只回一句情绪话。所以本插件把「被问细节时可以讲 200~400 字、分 2~4 点」写进了 **核心记忆块** 和 **工具描述** 里，作为例外。

如果你不想要这个行为，清空 `detail_hint` 即可。

## 设计说明（关于提示词缓存）

用户直接分享视频链接时，插件**不会修改 `req.system_prompt`**。

系统提示词是提示词缓存的前缀，往里追加字幕（最多 6000 字）会让整段前缀失效，
每个带链接的请求都要重新 prefill，既费钱又拖慢首字。

所以素材是通过 `req.extra_user_content_parts` 追加的，并标记为**临时内容**
（`mark_as_temp()` / `make_as_temp()`），只对当轮可见、不写入会话上下文。
不带链接的普通对话完全不受影响，系统提示词保持逐字节稳定。

> 0.1.1 起修改。0.1.0 用的是 `req.system_prompt +=`，被插件市场以「破坏缓存命中率」驳回。

## 常见问题

**Q：它答得出「今天看了什么」，但问细节时还是泛泛而谈。**
A：先看日志有没有 `Added llm tool: bilibili_read`；再看提问后有没有 `Agent 使用工具: ['bilibili_read']`。没有调用，多半是 `detail_hint` 被清空或改坏了。

**Q：提示「MemoryCompanion 未就绪」。**
A：没装或没启用 `astrbot_plugin_memory_companion`。插件其它功能（按需解析）不受影响。

**Q：同步一直接不到内容。**
A：检查 `digest_dir` 是否存在、文件里是否有形如 `日期 · BV · 标题 · ...` 的行；`skip_keyword` 是否把你要的都过滤掉了。

**Q：拉不到字幕。**
A：bili-cli 没登录、或者视频本身没有字幕也没有官方总结。工具会如实返回「取不到」，不会编内容。

**Q：会被第三方服务看到我看什么视频吗？**
A：不会。所有请求都走本机 bili-cli，没有任何第三方解析接口。
